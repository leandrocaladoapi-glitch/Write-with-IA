## Opening hook

The document is called `final-FINAL-v14-USE-THIS.md`. You know the number is a lie because you remember v9: the month you "fixed" the midpoint by softening the sister's line, which broke the arc's cost beat, which you patched in v11 by *adding* a confrontation — which re-broke the midpoint's map-change — which v13 smoothed by cutting the confrontation's last paragraph, leaving the fight's outcome ambiguous, which you now believe is actually *more ambiguous than you intended* but you cannot reconstruct which version intended what, because every revision since v8 has been one long Tuesday of free-floating tinkering: a word here, a paragraph's rhythm there, then back to Chapter 4 because something *feels* off, then the midpoint again, then words — **revising in a circle, polishing prose whose structure you suspect but have stopped testing.**

This is the most expensive failure mode in fiction: not laziness — *activity without a pass system*. The fix is architectural, and this chapter installs it: **one pass, one job, in order** — structure, character, scene, line, continuity — each pass a *bounded expedition* with its own checklist, its own machine instruments (the chapter's three cards: PC-20 developmental reader, PC-21 constrained line editor, PC-22 continuity checker), its own change-log, and its own **done criteria** so the circle stops on *paper* instead of on exhaustion. By the end you'll have run a full pass on real pages, adjudicated every machine suggestion in writing (the standing rule — now load-bearing at scale), and be able to state, with evidence, whether your draft is done — the question v14's filename has been *performing* instead of answering.

## Learning objectives

By the end of this chapter, you will be able to:

- [ ] Run the pass system: structure → character → scene → line → continuity, one job per pass, in order.
- [ ] Deploy AI as developmental reader (PC-20), constrained line editor (PC-21), and continuity checker (PC-22) — each on its own pass.
- [ ] Keep change logs that make revision decisions reversible, and adjudicate machine suggestions at scale without rubber-stamping.
- [ ] Recognize when a draft is done — written criteria, not vibes.

## The pass system

**One pass, one job.** The entire method in four words, and every part of it matters. *One job* — a pass looking for structure ignores your comma habits (the line pass's job) and your character's eye color (continuity's); single-purpose attention is what lets both you and the machine *find* things, because a mind — or a prompt — asked to "review everything" answers with the most available complaint (fluency-shaped nitpicks) and misses the expensive ones. *In order* — structure before scenes, scenes before sentences: fixing prose inside a structurally broken chapter is *paid polishing of soon-to-be-cut material*, and fixing a scene's beats before its structure is guaranteed rework (the order is also the *money* order — cheapest corrections first, per the Chapter 2 law). *Passes* — bounded: each has an entry condition (checklist version ready, previous pass's changes *applied and minted*), an exit condition (checklist + log complete), and a *never mid-pass* rule: you do not "just quickly fix" a line-level typo you notice during the structure pass — you *note it in the line-pass queue* and keep looking at structure (the noted-typo gets fixed anyway; what matters is your eyes never left altitude).

The five passes, at the resolution this book teaches (each with its question and its instrument):

| # | Pass | The one question | Primary instrument | Scope unit |
|---|------|------------------|--------------------|-----------|
| 1 | **Structure** | Does the *order and pressure* deliver the skeleton's stakes and climax? | PC-20, run outline-vs-draft | whole draft (or per-part for novels) |
| 2 | **Character** | Does every major character's chain/arc show *in the prose* — sheets vs. pages? | arc tracker (PC-19 input) + interviews if dry | cast, per appearance |
| 3 | **Scene** | Does every scene's goal/conflict/outcome land — and the endings turn? | scene checklist (below), Ch 4 anatomy | scene by scene |
| 4 | **Line** | Do the sentences sound like me, tightened to the style sheet? | PC-21 (constrained) + your red pen | paragraph by paragraph |
| 5 | **Continuity** | Does anything contradict — facts, props, voices, rules? | PC-22 + bible-first batches | cross-document |

**Novels split passes by part** (structure pass on Part I before Part II is drafted — earlier detection, cheaper always); short stories and novellas run each pass whole-draft (the unit fits attention). Between passes: *apply kept changes → mint draft number → changelog line → bible/outline sync if facts moved → next pass's entry check*. That inter-pass ritual (Ch 7's mint extended) is what makes passes *reversible*: each draft number corresponds to "structure fixed," "character reconciled," etc. — so a line pass gone wrong restores one number, not one week.

**The per-pass checklists** — the chapter's reusable core (these five, verbatim, are what Appendix C cross-references; adapt wording to your project, keep the *questions*):

```text

[ ] Outline-vs-draft diff: every outline beat has prose — or an
    adjudicated outline change (two-rule stand, changelog'd)

[ ] Setup/payoff ledger closed (PC-11's columns, now vs. pages)

        in the log (waivers are decisions rows, not silence)

    past 3 chapters without adjudication)
[ ] Blind voice test run on current draft (PC-18 — conf ≥4 on leads)
[ ] Unearned-warmth audit run (Ch 11's — clusters adjudicated)
[ ] Interviews triggered only where sheet-vs-page disagreements
    remain (each answered detail consumed by a beat or filed raw)
[ ] PASS LOG + any sheet v-next changes changelog'd

PASS 3 — SCENE (entry: draft-(N+2); scene list extracted)
[ ] Every scene labeled G/C/O in one line (missing O = cut or fix
    queue — no third category)
[ ] Every scene's last line passes the "cover everything above"

[ ] Tell inventory: only the four healthy types (Ch 4's cookbook);
    any tell doubling as emotional climax → staged or moved
[ ] Sequel beats present or consciously cut (reaction not vanished)
[ ] Sequel/scene transitions have no unexplained time-jumps
[ ] PASS LOG + cut-list finalized (cuts executed NOW — into cuts/

PASS 4 — LINE (entry: draft-(N+3); style sheet CURRENT; banned lists

[ ] Style sheet sweep: banned constructions (search strings) — zero
    hits, or waived rows
[ ] Voice: read-aloud of 3 random pages — rewrites only where your
    ear stops (not where habit nags)
[ ] PC-21 run per chapter WITH constraints (length-retention + lock
    list + no-new-information rule — see card); diffs adjudicated
    line-by-line; accept rate logged (see done-ness below)
[ ] Generic-sensation sweep (the twelve "heart hammered"s — one
    channel per scene max)
[ ] PASS LOG + draft-(N+4) mint

PASS 5 — CONTINUITY (entry: draft-(N+4); outline/bible synced)
[ ] PC-22 full battery in bible-first batches (names, dates, ages,
```

The checklists look long written out and take about ninety minutes each *in practice* — because most boxes are already checked by the system (the tracker filled at mints; the bible synced at mints; the style sheet maintained since Ch 14's template — the pass system *collects* the discipline the whole book has been installing, which is why it runs lean for readers who did the Project tiers and feels impossible for readers who didn't. If you're the latter: this chapter's honest advice is *go build the artifacts* (Ch 7's folder, Ch 3's sheets, Ch 14's sheet) — passes run on documents, not on intentions.

## AI in each pass

Three instruments, one per major pass — each card a *bounded deployment* of the same machine whose unbounded use created the v14 problem:

> PROMPT CARD PC-20 — Developmental reader (full pass)
>
> ```text
> <!-- PC-20 v1 · tested 2026-09 · generic, no model-specific syntax -->
> Role: developmental reader — FIRST READER, not editor: you
> experience the draft as a reader and report; you do not rewrite.
> Context: SKELETON + outline-current + story rules (§5) + length/
> structure target — pasted from the bible pack. Draft below (batch:
> [part/chapters — full scenes, never summaries]).
> Task: reader's report in this order, each finding location-quoted:
> 1. PROMISES: what does the draft seem to promise (premise, tone,
>    turn)? — quote the evidence lines.
> 2. PAY-OFF TRACK: where did your reading PULSE (lean-in) or
>    SAG (checked-out)? Give chapter/scene numbers + the exact
>    paragraph you noticed it. Sag = where you'd skim as a paying
>    reader — be specific about WHY (pressure / confusion /
>    familiarity).
> 3. CHARACTER READ: for each major character: what you believe
>    about them now + the line that created the belief. Flag any
>    belief that CONTRADICTS the pasted sheet (quote both sides).
> 4. ENDING DEBT: what does the draft's ending owe, given its
>    promises — and does the last quarter start paying?
> 5. BLIND SPOTS: three things a reviewer would raise that you
>    CANNOT evaluate from this batch alone (label: needs next
>    part / needs outline / genuinely unsure).
> Format: numbered sections, quotes required, damage implied by
> order (worst first within each section). NO praise section. NO
> rewritten prose. If a section has no findings: write "none found
> — checked: X."
> ```

PC-20's design talks back to everything Ch 5 taught: **first-reader framing** (experience, don't fix — "sag" is a *reading experience* report, and experience-reports are where the prediction engine's pattern-comprehension genuinely shines: it has "read" ten million pacing curves and can pattern-match your *felt* midsection against them — hedged always as *a reader's report, one reader, who cannot buy your book* — which is exactly the caveat Ch 13 will ram home about simulated feedback generally); **promises-vs-payoff** (grounds the report in *your* skeleton — else it grades against generic expectations and your deliberate kishōtenketsu *ten* reads as "underpowered midpoint" — the desk needs your aims or it audits the average book); **quotes everywhere** (every finding auditable in seconds — unlocated notes are vibes, vibes don't adjudicate); **blind-spot section** (the model *declaring its ignorance boundaries* — trained honesty, not assumed — findings it *can't* make are as valuable as ones it can, because they map your *beta* questions for Ch 13); **no praise section** (F-05's frame at full strength — the wind-down compliment is structurally banned, not just discouraged). Run it **once per structure pass**, fresh session, per-part for novels (batches = full prose, never your summaries — summaries audit the summary).

> PROMPT CARD PC-21 — Line editor (constrained)
>
> ```text
> <!-- PC-21 v1 · tested 2026-09 · generic -->
> Role: line editor under STRICT constraints; your changes must be
> justifiable against my style sheet (pasted: banned list, rhythm
> preferences, voice notes) — pretty-for-its-own-sake is a failure.
> Chapter below. Rules:
> 1. TARGETS ONLY: filter words (just/really/quite/somehow),
>    redundant doubles (began to start), passive where agent known,
>    dialogue-tag adverbs, sentences >25 words WITHOUT deliberate
>    rhythm justification (list any you keep and why).
> 2. PRESERVE ABSOLUTELY: proper nouns & spellings, POV/distance,
>    tense, all lock-list constructions, every sentence in a
>    character's fingerprint speech, my unusual syntax if marked
>    [!mine].
> 3. NO NEW INFORMATION: you may delete and tighten — you may NOT
>    add images, metaphors, or intensifiers. Word count: ≤100% of
>    original (shrinking preferred).
> 4. OUTPUT: (a) diff-style list: ORIGINAL → EDITED + reason tag
>    from [filter|double|passive|tag-adverb|long], (b) then full
>    clean chapter, (c) counts: changes n, words before/after.
> I accept/reject per row; rejections are final.
> ```
`

The constraints *are* the safety system: **targets-only** (the machine's line instincts without targets = thesaurus-swap theater, Ch 14's enemy — bounded, it becomes a *mechanical sweep* of items your style sheet already names); **preserve-absolutely** (fingerprint speech and marked-my-syntax protected *by name* — voice anchors' written guarantee extended into the pass; the `[!mine]` marker habit — you tag your deliberate weird sentences *before* the pass, the editor's job starts where your permission ends); **no-new-information** (the deepest rule — unconstrained line editors *add* ("a lantern of hope flickered" — injected lyricism, F-01's cousin at sentence scale); forbid addition and the pass can only subtract and straighten, which is what *editing* means); **≤100% words + per-row reasons + your veto** (adjudication at the row level — the pass's log *is* the decisions file for a chapter, and "I accept/reject per row" stated *in the prompt* keeps the model's default toward wholesale acceptance from framing your own review: the prompt reminds *you* that rejection is the designed outcome for probably half its rows).

> PROMPT CARD PC-22 — Continuity checker
>
> ```text
> <!-- PC-22 v1 · tested 2026-09 · generic -->
> Role: continuity auditor — bible-first, quotes-or-nothing.
> Context: BIBLE EXTRACT (names list verbatim + relevant §2 sheets +
> §3 timeline slice + §5 rules + never-say lists) pasted ABOVE the
> chapters — the extract is your ONLY source of truth for "correct."
> Chapters: [batch of 2–3 full chapters — never more on one desk].
> Battery, separate tables per category:
> A. CONTRADICTIONS: passage | bible fact | chapter — only where the
>    pasted extract covers the fact. If unsure whether bible covers
>    it: row marked "uncertain — needs bible check," NOT a guess.
> B. NAMES/SPELLINGS: every proper noun occurrence vs. names list
>    (typo-level precision).
> C. DATES/AGES/TIME: reconstruct the timeline slice from the
>    chapters; flag any sequence impossible under §3.
> D. PROPS/TRAITS: scars/handedness/objects-in-rooms vs. §2/§4 —
>    quote both sides.
> E. RULES §5: banned words/constructions/assurances — hit lists.
> F. POV/TENSE: interior-access sentences (every "felt/knew/
>    remembered") — list; flag any non-anchored.
> Output: six tables, quotes mandatory, no prose commentary, no
> suggestions. Uncertainty is a ROW TYPE, not a failure.
> ```

PC-22 is Chapter 5's type-split made executable — **internal claims checked against your documents, never the world** ("bible extract is your ONLY source of truth": this pass must *never* wander into "actually, February storms in that region…" — external verification is Ch 15's research discipline, separate pass, separate protocol); **batches of 2–3 chapters** (the shared desk's width — 40 chapters pasted = early chapters falling off *silently* = confident misses, exactly the amnesia Ch 5 warned; batching with the extract *re-pasted each batch* is the whole trick); **uncertainty-as-row-type** (the anti-hallucination feature *in the schema*: a model forbidden from guessing marks gaps instead — "needs bible check" rows go to *your* bible work, keeping the pass's precision high enough that you trust its hits — a checker with false-positive mush gets *skipped* next time, and a skipped checker is how v14's scar changed hands in chapter 9); **six tables = six searches** you'd run yourself if you had a month (names: near-mechanical; interior-access: the Ch 4 Oracle check at machine speed; never-says: exact-string) — the machine here isn't judging, it's *grep-ing with quotes*, which is its most trustworthy job in this entire book, and the reason continuity is the pass where AI assistance is *least* optional for long projects.

**Deployment cadence:** PC-20 once (structure pass); character tools from Ch 11 (character pass — already run *during* drafting, *verified* here); scene checklists hand-run (scene pass — the machine's first-reader pulse report from PC-20 already told you *which* scenes sag; the scene pass *fixes* them with your anatomy labels); PC-21 per chapter (line pass — bounded by chapter so row-level adjudication stays humanly reviewable — a whole-draft PC-21 dump is 400 unadjudicated rows, i.e., F-07 with extra steps); PC-22's battery in batches (continuity pass). Notice what *isn't* machine-run: the scene pass (your G/C/O labels — Ch 4's skill must stay sharp or atrophies; the machine *prepared* the pass with sag-locations, but the labeling reps are yours), the *acceptance* decisions in every other pass (row-veto stated in prompts, exercised by you), and the done criteria below (a machine cannot want your book to stop — only you can declare stop).

## Change logs and done-ness

**The change log** is the pass system's spine — one section per pass, rows *at decision time* (not reconstructed later; a pass's log written from memory is fan fiction). Format (extends the changelog.md from Ch 7 — *mints* at the file's top level, *pass rows* in `logs/pass-N-structure.md` etc., each row linking its mint):

```text
2026-09-26 · PASS 1 (structure) · draft-04 → 05
S1 | PC-20 sag @ ch4-5 (quote: "arranged the transport...") | KEPT |
    cause: want-gap mid-ch5 (tracker agreed) | fix: ch5 rebuilt on
    beat-level want (notary-hours micro-pursuit promoted from
    outline-v3 insert) | mint 05
S2 | PC-20 promises-read: "administrative never resolves cleanly"
    vs. skeleton ending "keys kept" | OVERRIDE-READER | my promise
    IS resolution-with-open-schedule — reader misread §?? → FLAG:
    ending needs one clearer image beat (queued scene pass, not
    structure) | no mint
S3 | stakes-invoice: climax quote MISSING the "Selvagem posting"
    proper noun (planted ch2, absent ch12) | KEPT | fix: restored
    in climax line | mint 05 (with S1)
[... every kept/rejected/waived — k kept of n found, stated]
```

Row anatomy, named because the names matter in adjudication: **ID | finding-with-quote | verdict (KEPT / REJECTED / OVERRIDE-* / WAIVED / DEFERRED-to-pass-X) | one-line reason | action + mint-link.** The verdict vocabulary *forces the taxonomy* the book's been building: **OVERRIDE-READER** (above: the machine's developmental read *disagreed with the skeleton* — you sided with your aims; the row preserves that the challenge *happened* without letting it win by default — the golden rule at developmental scale); **WAIVED** (finding valid, fix declined — "ch7 braid is slow *by design* (storm-foreshadowing needs the slowness)" — waivers prevent re-finding (the next pass's reader will sag there *again*; the waiver row *pre-answers* it — cited in the next prompt's context: "known waists: ch7 slowness — WAIVED pass-1 row S4, don't re-flag")); **DEFERRED-to-pass-X** (the noted-typo rule institutionalized: altitude discipline *with* memory); **REJECTED-with-mechanism** ("suggests adding flashback — rejected: no backstory paragraphs rule §5 + Ch 3 dosing schedule" — rejections cite *rules*, not moods, which both disciplines *your* taste and documents authorship (Ch 15's evidence class, again)). Every pass's log ends with the **k-of-n line** and a **density note** ("structure: 14 found, 9 kept — high keep-rate on want-gaps, low on tone notes (reader over-indexed style at structure altitude — noted for next time PC-20 context: add 'structure altitude — defer style'") — density patterns tune the *prompts* (v2 bumps) and tune *you* (what you keep at scale is your actual editorial priority list, revealed in numbers instead of self-story).

**Done-ness: written criteria, checked like a checklist.** The v14 disease is *vibe-done* ("feels almost there… maybe one more pass") — the cure is a criteria block you write **before Pass 1** (not after, when every criterion would morph to fit fatigue), stored with the project (`done-criteria.md`), and *checked only at Pass 5's exit*:

```text
DONE CRITERIES — "Low Tide" (written pre-pass-1, 2026-09-26)
1. All five pass logs complete, cycle count ≤ 1 full cycle after
   betas (second cycle = STOP → F-07 diagnosis).
2. k-of-n keep-rate across last two passes < 30% (convergence
   signal — the machine and I are mostly agreeing to leave it
   alone).
3. Style sheet: zero banned-list hits in two consecutive full
   read-throughs.
4. Blind voice: I can identify my-vs-machine paragraphs at ≥80%
   on a shuffled 10-paragraph sample — and the four I miss I can
   DEFEND (not just tolerate).
5. Stakes invoice + payoff ledger + arc tracker: zero open flags.
6. One cold full read (≥48h from last edit): no note surprises
   me that I hadn't already seen in a pass log — the draft has
   stopped teaching me new structural things.
7. External gate: Ch 13 beta round returned + triage applied +
   feedback-to-changes table rows all resolved (waived rows cited
   vision).
— Then: DONE. Not "done enough." The document says DONE, or the
  cycle runs again with a named failing criterion.
```

Read criteria 2 and 6 slowly — they're the load-bearing pair. **Keep-rate <30%** (operationalized: when your adjudications mostly say "leave it," the work is *finished being found* — divergence of a converging system; above 50% across two passes = still moving = keep working or F-07 if *the same findings recur* — recurring-findings ≠ productive-findings, the circle's distinguishing feature); **cold-read with no surprises** (the experiential proof — passes are analyses, the cold read is *synthesis*: a draft that still ambushes you structurally has pass-gaps; a draft that merely *bored* you at 60% of its length has a criterion-2 problem, not a quality problem — boredom-without-new-notes = normal, novels stop being new before they stop being *done*). And criterion 4's **defend-not-just-tolerate**: the done standard isn't machine-free prose (Ch 1 never promised that) — it's *ownable* prose: every survivor, either yours or yours-by-adjudication, able to answer "why does this sentence exist?" with *your* sentence. That's authorship as the done-state's definition — which is why the criteria file, like everything else in this book, ends up being less about the machine than about the name on the cover.

The circle stops here: **passes with entry/exit conditions, instruments bounded by cards, adjudications in rows with verdict vocabulary, mints between passes, criteria written before starting and checked at the end.** v14 dies today; `draft-05` with five logs is born. What remains is the gate: whether *your* five logs and *your* criteria are enough — or whether the draft needs readers who *aren't* you or your assistant. That gate has a name and a chapter: feedback, betas, and the triage that turns opinions into tables. Chapter 13.

## Pitfalls

> PITFALL — **Non-converging loops (F-07).** *Symptom:* `draft-14`-style naming; revisions that re-fix what earlier passes fixed (the sister-line/midpoint/confrontation circle from the hook — each fix breaking what the last one held); keep-rates that *don't decline* across passes; the tell: **the same finding reappears after being fixed** (new findings = work remaining; *recurring* findings = the loop itself is the defect); emotionally: revision feels like *whack-a-mole with your own standards* — standards you can't state because they were never written as criteria. *Why it happens:* no pass system (every session is all-altitudes — structure doubts prompt line-tinkering which breaks scenes which *re-raise* structure doubts — the circle's physics: *simultaneous optimization of coupled variables without ordering*, the exact thing "one pass, one job, in order" exists to prevent); done-by-vibe (no pre-written criteria → the finish line *moves* with mood and fatigue → "one more Tuesday" forever — and the machine makes this *worse* unbounded: PC-21-style rewrites available on demand mean the supply of possible edits *never reaches zero* — convergence isn't waiting for suggestions to stop, it's your *accept-rate* crossing your *written* threshold); adjudication abdication at scale (400 unadjudicated PC-21 rows = decisions made *by default acceptance* — the golden rule's mass-violation, which feels like nothing until draft-14); and **fix-echo** — changes made without changelog rows *can't be recognized as already-done* by next pass's instruments (the sister-line gets "fixed" thrice because fix #1 left no row for #3's reader to see — logs aren't bookkeeping, they're the loop's *memory*). *Fix (in diagnostic order — name which of the four you have):* (1) **recurring-findings signature** → you're between passes illegally: restore the current pass's entry condition, finish it *fully* (log + k-of-n + mint), and paste *prior pass logs' WAIVED/kept rows* into the next pass's context (the instrument now *sees* what's done — the waiver-citation protocol, doubled); (2) **keep-rate >50% across two passes** → you're not converging *or* looping — you're **under-revising the early passes** (kept findings keep appearing = structure/character still moving): *re-run pass 1* deliberately (cycles allowed once per beta round) rather than grinding altitude-5 line passes on a moving target; (3) **vibe-done** → criteria file: write it *today* pre-pass if possible, or freeze v1 and stop renegotiating; check ONLY at pass-5 exit; criterion 2's keep-rate threshold replaces the mood's vote; (4) **abdicated-scale** → chunk PC-21 by chapter with row-cap attention (if you can't adjudicate 40 rows in one sitting honestly, the batch was too big — smaller desks), "I accept/reject per row" re-stated in the prompt, and the standing rule restated as arithmetic: *a pass with an acceptance rate you never reviewed is not a pass, it's a paste*. *Prevention* (the system's steady-state): entry/exit checklists (can't start pass 4 with a stale style sheet — the entry conditions *block* the anxious-skipping that starts circles), the inter-pass ritual (fix → mint → log → sync → *then* next altitude), criteria-before-pass-1 (done defined while you still have standards-energies, not during week six's fatigue), k-of-n density notes feeding *prompt v2 bumps* (instrument converges alongside you — the loop's quiet compounding), and one human gate per cycle (Ch 13 — new external information is the *only* legitimate circle-breaker when logs say you're converged but criterion 6's cold-read still surprises; ## Key takeaways

- **One pass, one job, in order** — structure → character → scene → line → continuity — each with entry/exit conditions, a checklist, and a mint *after* kept-fixes apply: cheapest corrections first, paid polishing never applied to soon-to-be-cut material, altitude changes on schedule instead of by anxiety.
- **Three bounded instruments:** PC-20 as *first reader* (promises, sags with quotes, blind spots — one reader who can't buy your book), PC-21 as *constrained sweeper* (targets-only, preserve-lists incl. `[!mine]`, **no new information**, row-level veto), PC-22 as *bible-first grep* (batches of 2–3 chapters, uncertainty-as-a-row-type, internal-claims-only — the most trustworthy machine job in the book).
- **Change logs are the loop's memory:** verdict vocabulary (KEPT / REJECTED-with-mechanism / WAIVED-citing-next-context / DEFERRED-named-pass / OVERRIDE-READER / EXTERNAL) makes decisions visible, prevents fix-echo, documents authorship (Ch 15 will call this evidence), and density notes tune the *instruments* alongside your taste.
- **Done is written before you start** — criteria file drafted pre-pass-1 (keep-rate thresholds, cold-read test, voice-ownability, zero open flags, beta gate), checked only at pass-5 exit, renegotiated only via visible version rows: vibe-done is the disease; arithmetic-and-a-cold-read are the cure.
- **F-07 has four signatures and four fixes** (recurring-findings → re-enter passes properly + waiver-citation; non-declining keep-rate → re-run pass 1, stop grinding pass 4; vibe-done → criteria freeze; abdicated-scale → chunk + row-cap). The pass system's steady state isn't perfection — it's a converging, *documented* curve that ends at a gate you built in Chapter 13's direction: human readers, one cycle at a time.
